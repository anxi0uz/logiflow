## Назначение и границы

Бэкенд логистической платформы: заказы на перевозку, автопарк, назначения,
маршруты, рекомендации диспетчеру и шесть видов внутренних PDF.
Фронтенд находится в отдельном репозитории и здесь не проверен.
Состояние публичного демо и сохранность прежних данных не установлены.

## Реализовано

- Go Core с PostgreSQL, Redis, JWT и HTTP API из `internal/api/api.swagger.yaml`.
- Lifecycle: `draft → ready_for_dispatch → assigned → in_transit → arrived → completed`;
  отмена до начала перевозки; замена назначения до старта и отдельная передача груза в пути.
- Assignment фиксирует конкретного водителя, машину и интервал бронирования.
  Предложение живёт 15 минут. Пересекающиеся открытые назначения запрещает PostgreSQL.
- Расчёт маршрута через OSRM и цены при создании заказа; редактирование груза
  и окна черновика с пересчётом цены. Геокодинг через Nominatim.
- Python Dispatch читает Core DB отдельной ролью, ранжирует до пяти пар
  водитель/машина. Асинхронные запросы через NATS, ручной refresh через gRPC.
- Фоновое истечение предложений и очередь пересчёта после освобождения брони.
- Склады: оба конца маршрута сохраняются; receive/load/unload подтверждают менеджеры,
  start/complete требуют складских подтверждений; undo_load до выезда освобождает
  назначение, return_to_sender фиксирует выдачу после отмены. Очередь и журнал операций.
- Проблемы перевозки: поломка, повреждение, расхождение количества, отказ получателя;
  автоматические расхождения, однократные решения менеджеров, блокировки load/start/complete,
  уведомления и история в последующих PDF. Подробности в `incidents.md`.
- Передача в пути: запрос менеджера, подтверждения передающего/принимающего водителей,
  повторная проверка ресурсов, атомарная смена active назначения и сохранение истории.
- Python Documents: шесть видов внутренних PDF, отдельная БД, приватный gRPC,
  HTTP-ящик и скачивание через Core; права конкретных участников и уведомления.
- Transactional outbox/inbox, обработка повторных событий, изоляция невалидных событий.
- Go unit/HTTP/integration tests, Python pytest/Ruff, compose HTTP E2E и CI.

Локальная проверка 2026-10-11: Go с PostgreSQL/Redis (142 теста и подтеста,
без пропусков), pytest обоих сервисов, Ruff, go vet и расширенный HTTP E2E с PDF прошли.
Подробности и ограничения среды — в [development.md](development.md).

## Ограничения

- WebSocket движения — симуляция координат маршрута, реального GPS нет.
- Draft уже требует маршрут; неполный черновик без routing пока не поддержан.
- `driver_shifts` и `driver_documents` участвуют в проверках, но публичных
  endpoint для управления ими нет. Документы машин через API управляются.
- Нет общей идемпотентности команд, `expectedVersion` и optimistic locking.
- `order_status_history` записывается, отдельного API чтения истории нет.
- Текущие статусы водителя/машины и fallback на `license_expiry` отличаются
  от целевой модели в `CORE_DOMAIN_MODEL.md`.
- Юридические стороны договора, УКЭП и обмен через оператора/ГИС ЭПД отсутствуют;
  внутренние PDF не являются юридически значимой ЭТрН или путевым листом.
