# Демоданные

После запуска актуального Core выполнить из корня `make seed` (нужен Go).
Команда читает configs/config.toml и .env, подключается к PostgreSQL на
127.0.0.1 и требует уже применённую миграцию transport_parties_receipts.
Для другого адреса: `LOGIFLOW_DATABASE_HOST=... go run ./cmd/seed`.

Создаются 12 пользователей, 3 склада, 6 машин/водителей с документами,
7 контрагентов, 9 заказов с маршрутами, историей и складскими операциями.
Снимки для 19 PDF и запрос Dispatch сохраняются в outbox той же транзакции;
обработка требует работающих Core/NATS/Documents/Dispatch.
Демоадмин явно включён в получатели всех 19 PDF; для обзора набора можно
войти как admin@demo.logiflow.test. Это получатель демодокументов,
а не глобальное право любого администратора на чужие PDF.

## Вход

| Email | Роль |
| --- | --- |
| admin@demo.logiflow.test | Администратор |
| manager.moscow@demo.logiflow.test | Менеджер отправления, Москва |
| manager.spb@demo.logiflow.test | Менеджер Санкт-Петербурга |
| manager.kazan@demo.logiflow.test | Менеджер назначения, Казань |
| client1@demo.logiflow.test, client2@demo.logiflow.test | Заказчики |
| driver1@demo.logiflow.test … driver6@demo.logiflow.test | Водители |

Общий пароль новых демоаккаунтов генерируется случайно и печатается только
при создании. Можно заранее задать LOGIFLOW_DEMO_PASSWORD (12..72 байта).
Пароль не сохраняется в репозиторий и не меняется повторным запуском.

## Сценарии

| Номер заявки ДЕМО-2026-N | Исходное состояние |
| --- | --- |
| 1 | Черновик, реквизиты заполнены |
| 2 | Ожидает назначения; груз принят складом, рекомендации Dispatch |
| 3 | Предложение driver1/машине 1; срок 15 минут |
| 4 | Назначение принято driver2; требуется погрузка перед start |
| 5 | Груз в пути, driver3/машина 3 |
| 6 | Прибытие driver4; разгружено/принято 9 из 10 мест, открытая проблема |
| 7 | Завершённая доставка с передачей driver5 → driver6 и заменой машины |
| 8 | Отмена после складской приёмки; груз ожидает возврата отправителю |
| 9 | Завершённая доставка на обычный адрес, driver5 |

Большинство заказов принадлежит client1; отмена и адресная доставка — client2.
Отправление — Москва; назначение — Казань либо Санкт-Петербург.
Каталоги заказчиков приватные, общий перевозчик принадлежит admin.

Данные явно помечены ДЕМО. Названия вымышлены; ИНН нужны для проверки формата,
а не утверждения реальной принадлежности. Геометрия/дистанции иллюстративные,
без обращения к OSRM; новые обычные заказы рассчитывают маршрут штатно.
Смены не синтезируются: действует обычный fallback без расписания;
seed не моделирует соблюдение режима труда/отдыха или подписанные документы.

## Повтор и проверка

Seed — явная команда, не миграция и не автоматический шаг запуска.
Одна транзакция и advisory lock защищают от частичной записи и конкуренции.
Стабильные UUID отделяют набор от чужих данных. При наличии demo admin
повтор не создаёт записи, не сбрасывает пароли и не откатывает прогресс.
Коллизия ID/email/slug с существующими данными откатывает всю вставку.
Вручную удалённые части набора автоматически не восстанавливаются.

Даты считаются при первом создании. Предложение истекает штатно, плановые окна
со временем устаревают; повтор не переносит их вперёд. Для нового показа можно
создавать новые заказы через API/интерфейс, используя готовый каталог.

2026-10-11: проверены атомарность при коллизии, конкурентный запуск,
повтор без сброса пароля/прогресса, обязательность load и start реальными командами.
На пользовательском стенде прошли 12 входов, чтение заказов/контрагентов/очередей,
передачи и приёмки, изоляция заказчиков. Проверены список всех 19 PDF шести типов
и скачивание каждого под демоадмином; в браузере — список и кнопка скачивания.
У ранее созданных 19 PDF получатель demo admin добавлен отдельно, строго по
UUID демозаказов и их владельцев; повтор seed сам старые документы не меняет.
