# Направление проекта

Цель: учебная система управления внутренними грузовыми автоперевозками РФ.
Доменная модель должна объяснять реальный рейс, а документы — честно отражать
границы внутреннего учёта. Реализованные правила и юридические источники:
[logistics-rf.md](logistics-rf.md).

## Уже выполнено

- DB/Redis integration tests и изолированный HTTP E2E; зависимости закреплены в CI.
- Передача груза в пути при смене водителя, машины или обоих ресурсов,
  подтверждения участников, защита бронирования и сохранение истории.
- Приёмка, погрузка, разгрузка и очередь заказов складов с правами менеджеров.
- Снятие погрузки до выезда, выдача отправителю после отмены, учёт проблем перевозки
  и автоматических расхождений, блокировки и решения ответственных менеджеров.
- Шесть внутренних PDF с неизменяемыми снимками и доступом участников.

## 1. Подключение фронтенда

В отдельном frontend-репозитории добавить создание запроса передачи менеджером,
подтверждения водителей, историю назначений/передач и выбор документов в ящике.
Подключить очереди складов, формы всех пяти операций, журнал проблем и решений;
доступные действия
определять по роли, Order.status и warehouseStage.
Показывать 409 при конфликте ресурсов, срок запроса и текущего ответственного.
Готово, когда сценарий заказа со сменой водителя демонстрируется без ручных HTTP-запросов.

## 2. Управление автопарком

Добавить API смен и водительских документов с правами и правилами изменения
при открытых назначениях. Документы машин уже имеют API.
Проверить parity eligibility Core/Dispatch, особенно даты и границы интервалов.
Готово, когда менеджер готовит ресурс к назначению без прямого SQL.

## 3. Полнота учёта перевозки

Добавить контрагентов и роли грузоотправителя, получателя, перевозчика,
условия договора; уточнить фиксацию фактической погрузки/выгрузки, количества мест,
пломб, замечаний и подтверждения получателя. Сейчас recipientName необязателен.
Вынести чтение общей истории статусов в API и улучшить аудит команд.
Перед расширением согласовать обязательные поля и сценарий защиты.
Для окончательного отказа получателя спроектировать отдельный обратный рейс;
сейчас отказ можно разрешить согласованной приёмкой, возврат реализован только
с исходного склада после отмены до выезда. Историю проблем и решений уже хранит Core.

## 4. Эксплуатация

Наблюдаемость outbox/release queue, задержки PDF, restart/retry и восстановление volumes.
Безопасный воспроизводимый конфиг вместо tracked `.env`; состояние старого k3s неизвестно.

## Отдельный промышленный этап

Юридически значимые ЭПД требуют оператора/ГИС ЭПД, актуальных форматов, УКЭП,
полномочий подписантов и обработки исключений. PDF-шаблоны этого не заменяют.
Путевой лист требует медосмотра и технического контроля, которых в домене нет.
Реальный GPS/ETA, международные/опасные грузы, бухгалтерия и объектное хранилище
не входят в реализованный учебный контур.
